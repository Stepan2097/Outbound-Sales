# ESP для cold email — пакет для розробників (Outbound-Sales)

Зібрано 10.10.2026 Менеджером із дошки (дев-чати не бачать описів, коментарів і вкладень тасків — тут усе в файлах).
Це **вихідні вимоги**, не код: нічого з цієї теки в прод не їде. Вирішуй, чи комітити її (корисно як специфікацію).

## Головне
- ESP будуємо ВСЕРЕДИНІ проєкту Outbound-Sales (слова власника 09.10: «це все ми робимо в проекті оутбаунд»), поряд з прогрівом LinkedIn і екранами (Прогрів, Вхідні, Контакти, Налаштування). Принцип: чим простіше, тим краще.
- ESP — оркестратор поверх скриньок Google Workspace: вирішує, кому, з якої скриньки і коли надіслати. Захист від помилок важливіший за функції: баг (подвійна відправка, пачка листів, HTML замість тексту) спалить домени швидше за погану базу.
- Чекліст ([checklist.md](checklist.md)) має ПРІОРИТЕТ над референсом Snov: у Snov є відкриття, кліки, HTML і трекінг — у нас НІ (лише text/plain, без пікселя й переписаних посилань, звіти без відкриттів і кліків).
- Скріни Snov.io ([screens/](screens/)) — приблизний вигляд у стилі наявного інтерфейсу Outbound, не копія.
- НІЯКИХ реальних листів назовні до приймання ESP 11 (його приймає власник). До реальних ключів — заглушка Gmail API.
- Секрети (ключі service account, DQS-ключ) — лише файл/змінна середовища, не в код, таски й комітам.
- Блокуючих питань не ставити; рішення приймай сам і записуй у таск «Рішення: … — бо …».

## Порядок і розподіл
P0: ESP 1–10, потім ворота ESP 11 (приймання), далі P1: ESP 12–16, P2: ESP 17.
- Outbound-Sales: ESP 1 → 2 → 3 → 4 → 5 (підключення пошти, лист, заголовки, ліміти, ланцюжок).
- Outbound-Sales2: ESP 9 → 10 → 6 (дані, безпека, перевірки перед відправкою), далі ESP 7 → 8, коли буде ESP 1.
- Спільне (server.mjs, схема стану) — малими комітами, fetch перед кожним.

## Рішення по ESP 1 (Менеджер, 10.10)
Service account з domain-wide delegation у кожному нашому Workspace (не зовнішній OAuth-застосунок: він вимагає верифікації Google). Код — за інтерфейсом «конектор скриньки», щоб потім додати Internal OAuth. Бо ми самі адмінуємо Workspace, паролів немає, верифікація не потрібна. Реальні ключі дає власник у чаті дева; до цього — заглушка Gmail API.

- `screens/03-create-campaign.png` — «Create a campaign»: з шаблону або з нуля. → **ESP 5**
- `screens/04-campaign-list.png` — Список кампаній: Create campaign, Export statistics, Add email account, Add LinkedIn account, папки, таблиця (статус, надіслано, відповіді, bounce, власник, одержувачі, список); жовті банери про помилку скриньки. → **ESP 5, ESP 16, ESP 8**
- `screens/05-campaign-builder.png` — Конструктор кампанії: 4 кроки Sequence → Recipients → Sending options → Review; блоки Email, LinkedIn, Condition, Delay, Goal; A/B test. → **ESP 5 (затримки, умова «відповів — зупинити»), ESP 4 (Sending options), ESP 12 (A/B), ESP 13**
- `screens/06-reports.png` — Reports: вкладки Email / LinkedIn / General, фільтри (кампанії, акаунти, власники, період), надіслано (перші листи / фолоуапи), Deliverability (delivered / bounced), воронка, відписки, автовідповіді, графік по годинах/днях/тижнях/місяцях, експорт CSV. → **ESP 16 (БЕЗ відкриттів і кліків — у нас їх нема)**
- `screens/07-leads-lists.png` — Leads: списки/папки, таблиця контактів з кольоровим статусом email (верифікація), Verify emails, Send campaign. → **ESP 6 («легко вибрати базу контактів»)**
- `screens/08-email-editor.png` — Редактор листа: тема, шаблон, змінні (Full name, First name, Last name, Sender account name, Country), spintax, dynamic content, Unsubscribe link, режим Plain text, Preview and test, Save as template. → **ESP 2, ESP 3, ESP 12 (у нас лише text/plain)**
