# Чекліст ESP для cold email v1 (09.10.2026)

P0 — без цього перший холодний лист не відправляємо. P1 — у перший місяць пілоту. P2 — згодом.


## Підключення пошти

- **[P0] Google OAuth без паролів** — Жодних паролів скриньок у базі чи таблицях. Токени зашифровані, доступ до них — лише сервісу відправки.
- **[P0] Як отримати доступ до скриньок у кількох Workspace** — Зовнішній OAuth-застосунок із Gmail-скоупами Google вимагає верифікації. Простіше: **service account із domain-wide delegation** у кожному нашому Workspace, або Internal-застосунок у кожному. Обрати до старту розробки.
- **[P0] Відправка через Gmail API** — `users.messages.send` з `threadId` для фолоуапів. За даними Snov, через API відповідей удвічі більше, ніж через SMTP (кореляція).
- **[P0] Відкликаний токен = пауза сендера** — Помилка авторизації чи блок акаунта → сендер на паузу, сповіщення людині. Не повторювати спроби в циклі.
- **[P2] Абстракція провайдера** — Microsoft (Graph API) додамо пізніше — не зашивати Google у бізнес-логіку.

## Лист і заголовки

- **[P0] Лише text/plain** — Одна частина `text/plain; charset=UTF-8`, без `text/html`. Наш урок: текст із Google Docs тягнув форматування, і лист ставав HTML.
- **[P0] Очищення шаблону при збереженні** — Знімати HTML-теги, стилі, нерозривні пробіли, невидимі символи. Шаблон із тегами не зберігається.
- **[P0] Ніякого трекінгу** — Без пікселя відкриттів, без переписування посилань, без трекінг-домену.
- **[P0] Заголовок List-Unsubscribe** — `List-Unsubscribe` (mailto + https на домені відправника) і `List-Unsubscribe-Post: List-Unsubscribe=One-Click`. Посилання — лише на домен, з якого йде лист.
- **[P0] Порожня змінна блокує лист** — «Hi ,» не відправляється: або нейтральна заміна, або лід пропускається з причиною.
- **[P0] Фолоуапи в тому самому треді** — Той самий сендер, `In-Reply-To` і `References`, «Re:» лише як справжня відповідь у треді.
- **[P0] Підпис лише текстом** — Ім'я, посада, ADvantage, сайт. Для США — поштова адреса юрособи. HTML-підпис із картинкою (як у старій таблиці) робить лист HTML.
- **[P1] Спінтакс по реченнях** — Варіанти цілих речень. Рендер один раз на ліда, зберігати фінальний текст і ID варіантів. Режим «половина кампанії без спінтаксу» для A/B.
- **[P1] Блок для ЄС і UK** — Для лідів з ЄС і UK автоматично додається коротке повідомлення, звідки адреса, і посилання на політику даних на домені відправника. Зберігати, яку версію отримав лід.

## Розклад і ліміти

- **[P0] Ліміт на сендера — сумарно по всіх кампаніях** — Ціль 35 на день, але фактичний ліміт = етап рампи (5 → 10 → 15 → 20 → 25 → 30 → 35).
- **[P0] Ліміт на домен** — Сума сендерів домену ≤ ~105 на день.
- **[P0] Кнопка «стоп усе» і пауза на кожному рівні** — Сендер, домен, кампанія, вся система.
- **[P0] Вікно відправки** — Пн–Пт, 08:00–17:00 за часовим поясом одержувача. Вихідні пропускаються.
- **[P0] Випадкові інтервали** — 12–40 хв між листами одного сендера, без пачок на початку години.
- **[P0] Без доганяння** — Пропущені листи не відправляються купою наступного дня — розподіляються в межах звичайного ліміту.
- **[P0] Ідемпотентність** — Ключ на «лід + крок». Повтор після збою чи таймауту API не дає другого листа.
- **[P0] Один лід — один сендер** — Весь ланцюжок з однієї скриньки. Лід не може бути в двох активних кампаніях.
- **[P0] Розклад кампанії в робочих днях** — Лист 1 — день 0, лист 2 — +3, лист 3 — +4 робочі дні. Налаштовується на кампанію.
- **[P1] Не більше 2 нових контактів з однієї компанії на день** — І ніколи з кількох наших доменів одночасно.
- **[P1] Рампа з умовою** — Крок угору лише якщо за тиждень bounce до 2%, немає 5.7.x і є відповіді. Інакше етап стоїть, людині — сповіщення.
- **[P2] Свята країни одержувача** — Пропускати державні вихідні.

## Перевірки перед відправкою

- **[P0] Глобальний список виключень** — Перевірка перед кожним листом, не лише при завантаженні. Відписки, «ні», hard bounce, скарги, клієнти, партнери — назавжди.
- **[P0] Верифікація не старша 30 днів** — Інакше лід не йде, позначається на повторну перевірку.
- **[P0] Фільтри пілоту** — Без catch-all, без role-адрес (abuse@, postmaster@, admin@…), без @icloud.com, лише одержувачі з MX на Google.
- **[P0] Фільтр країн** — Налаштовуваний список виключених країн. Зараз: Німеччина. PL, AT, DK, CZ, ES, IT, NL, Канада — за рішенням після юриста.
- **[P0] Обов'язкове джерело ліда** — Без джерела і дати отримання лід не відправляється.
- **[P1] Повторний контакт не раніше ніж через 90 днів** — Для тих, кому вже писали й хто не відповів.

## Вхідні: відповіді, bounce, відписки

- **[P0] Читання вхідних кожної скриньки** — Gmail API (history або push). Відповідь у треді → ланцюжок ліда зупиняється.
- **[P0] «У відпустці» і автовідповіді** — Розпізнавати (`Auto-Submitted`, типові теми й тексти) → переносити крок, а не зупиняти і не рахувати як відповідь.
- **[P0] Розбір bounce з кодами** — Листи від mailer-daemon: `5.1.1` → у виключення; `5.7.x` → тривога по сендеру; `4.x.x` — рахувати окремо.
- **[P0] Відписка того ж дня** — One-click, mailto і відповіді «ні», «unsubscribe», «remove» → глобальні виключення автоматично.
- **[P1] Класифікація відповідей** — Позитивна, негативна, переадресація, нейтральна. Зберігати сирий текст і мітку.
- **[P1] Відповідь зупиняє компанію** — Після відповіді від когось у компанії — ставити на паузу інших контактів цієї компанії в кампанії.
- **[P1] Спільна вхідна для команди** — Усі відповіді в одному місці зі швидкою відповіддю від того ж сендера.

## Автопаузи і тривоги

- **[P0] Bounce сендера** — Понад 2% за 7 днів або 3 bounce на останні 100 листів → пауза сендера.
- **[P0] Bounce нової кампанії чи джерела** — Понад 3% на перших 100–300 лідах → пауза кампанії, джерело на перевірку.
- **[P0] Помилки Gmail** — Перевищення ліміту, блок акаунта, масові відмови → пауза сендера, сповіщення.
- **[P1] Порівняння сендерів кампанії** — 0 відповідей на 80–100 листів при живому напарнику → прапорець і пауза.
- **[P1] Блоклисти щодня** — Spamhaus DBL (потрібен ключ DQS — публічні DNS їм не відповідають), SURBL, Validity Heatwave — для всіх холодних доменів і advantage-agency.co. Будь-який лістинг → пауза домену, тривога.
- **[P1] Монітор DNS** — SPF, DKIM, DMARC, MX кожного домену: зникло чи змінилось → тривога.

## Дані і звітність

- **[P0] Журнал подій лише на додавання** — Відправлено, відповідь, автовідповідь, bounce з кодом, відписка, помилка — з часом, сендером, кампанією, кроком.
- **[P0] Зберігати точний відправлений текст** — Тему, тіло, ID варіантів, Gmail message і thread ID.
- **[P0] Реєстр доменів і сендерів** — Домен: дата реєстрації, стан (старіє / рампа / активний / запас / виведений), статус DNS і блоклистів. Сендер: людина за ним, етап рампи, ліміт, статус.
- **[P1] Щоденний звіт по сендеру і домену** — Відправлені, bounce за кодами, відповіді, позитивні, відписки. Без відкриттів і кліків.
- **[P1] Звіт по кампанії, версії тексту, темі, кроку, джерелу ліда** — Частка відповідей і позитивних. Внесок кожного кроку — щоб вирішити, чи потрібен третій лист.
- **[P2] Експорт і видалення за email** — Для запитів людей про їхні дані: показати, звідки адреса і що надсилали; видалити, лишивши хеш у виключеннях.

## Безпека

- **[P0] Ролі й доступи** — Хто може запускати кампанії, міняти ліміти, бачити відповіді. Журнал дій адміністраторів.
- **[P0] Секрети поза кодом і таблицями** — Ключі сервісного акаунта, DQS-ключ — у сховищі секретів.
- **[P1] Строк зберігання** — Неактивні ліди видаляються або анонімізуються після визначеного строку; виключення лишаються назавжди.


## Приймання перед першим холодним листом (ESP 11)
- Тестова кампанія на 10–15 внутрішніх скриньок пройшла повний цикл: 3 листи в одному треді, відповідь зупинила ланцюжок, «у відпустці» переніс крок, відписка спрацювала того ж дня.
- «Показати оригінал» у Gmail: лише `text/plain`, є `List-Unsubscribe`, немає пікселів і переписаних посилань.
- Навантажувальний прогін: при штучно великій черзі жоден сендер не перевищив ліміт і інтервал, повтор після збою не дав дубля.
- Кнопка «стоп усе» зупиняє відправку за секунди.
