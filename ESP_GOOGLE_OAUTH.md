# Пошта · «Увійти через Google»

Скринька підключається так, як в Instantly чи Snov: «Пошта» → «Скриньки» → «Додати скриньку» → «Увійти через Google» → у вікні Google обрати скриньку → «Дозволити». Паролів платформа не бачить і не зберігає. Google віддає дозвіл (refresh token) на одну скриньку, і сервер тримає його зашифрованим ключем секретів (`OUTBOUND_SECRETS_KEY` або файл поруч зі станом).

Код:
- `esp/google-oauth.mjs` — вхід, токени, конектор Gmail на токені скриньки;
- `esp/mailbox-connect.mjs` — маршрути `/api/esp/oauth/google*`;
- `app/screens/mail-accounts.js` — панель «Скриньки для розсилки».

## Що робить власник (один раз)

1. **console.cloud.google.com**: проєкт → «APIs & Services» → «Library» → увімкнути **Gmail API**.
2. **OAuth consent screen**: тип **Internal**. Тоді скриньки вашого Workspace і його додаткових доменів підключаються без перевірки застосунку Google. Заповнити назву й пошту підтримки.
3. **Credentials** → «Create credentials» → «OAuth client ID» → **Web application**. У «Authorized redirect URIs» вставити адресу, яку показує панель «Скриньки для розсилки». На проді це `https://outbound-sales.169-58-60-245.sslip.io/api/esp/oauth/google/callback`.
4. Client ID і Client secret передати в чат розробки. Вони лягають у Coolify як змінні:
   - `ESP_GOOGLE_OAUTH_CLIENT_ID`
   - `ESP_GOOGLE_OAUTH_CLIENT_SECRET`
   - `ESP_GOOGLE_OAUTH_REDIRECT_URI` або `PUBLIC_URL` — необов'язково. Без них адреса повернення береться із запиту.

Скриньки з **іншого** Workspace підключаються після того, як їхній адміністратор додасть наш Client ID у довірені застосунки: admin.google.com → «Безпека» → «Керування доступом і даними» → «Елементи керування API» → «Керувати доступом застосунків» → «Налаштувати новий застосунок» → Client ID → «Довірений». Те саме Instantly просить для себе.

Особистий @gmail.com через цю кнопку не підключити: для зовнішніх користувачів Google вимагає перевірку застосунку. Для таких скриньок буде «Пароль застосунку (SMTP/IMAP)» — наступний крок.

## Що відбувається після входу

- Скринька стає відправником у реєстрі: етап рампи 5 листів на день, «хто» — той, хто підключив. Її домен додається в стані «рампа», якщо його ще не було.
- «Перевірити» читає профіль скриньки (нічого не надсилає).
- Якщо Google відкличе доступ (змінили пароль, прибрали дозвіл), скринька отримує стан «доступ втрачено» і стає на паузу. «Увійти знову» знімає паузу.
- «Відключити» відкликає токен у Google і ставить відправника на паузу. Свою скриньку відключає той, хто її підключив, чужу — адміністратор.
- Справжня відправка, як і раніше, лише з `ESP_LIVE_SEND=1`. Читання відповідей і ланцюжок — з `ESP_SEQUENCE=on`. Поки `ESP_LIVE_SEND` не ввімкнено, скриньки можна підключати й перевіряти.
- Сервісний акаунт з делегуванням (ESP_GMAIL_SETUP.md) лишається запасним шляхом для адміністратора домену. Скринька, яка увійшла через Google, завжди йде через свій токен.
