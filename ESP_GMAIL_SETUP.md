# ESP · підключення пошти (ESP 1)

Холодні листи йдуть зі скриньок Google Workspace через **Gmail API**. Один сервісний акаунт Google Cloud із **делегуванням на рівні домену** діє від імені кожної скриньки-відправника. Паролів скриньок і OAuth-згоди від кожної скриньки система не має й не потребує.

Код: `esp/gmail.mjs` (конектор), `esp/api.mjs` (`/api/esp`), екран — «Пошта» → «Налаштування пошти» → «Пошта для розсилки» (`app/screens/esp-mailboxes.js`).

## Що робить власник (один раз на домен)

1. **Google Cloud → IAM → Service accounts**: створити сервісний акаунт, вкладка *Keys* → *Add key* → JSON. Увімкнути **Gmail API** у цьому проєкті.
2. **admin.google.com → Безпека → Керування доступом і даними → Елементи керування API → Делегування на рівні домену** → *Додати*:
   - Client ID — `client_id` з JSON-ключа (його ж показує екран, коли ключ на сервері);
   - scopes, через кому, рівно ці:
     `https://www.googleapis.com/auth/gmail.send,https://www.googleapis.com/auth/gmail.readonly,https://www.googleapis.com/auth/gmail.modify`
   - перші два — для пошти (відправка, читання відповідей): вони в кожному токені. `gmail.modify` потрібен лише **прогріву пошт** («Прогрів пошт», `esp/mail-warmup.mjs`), щоб виймати наші ж листи прогріву зі «Спаму» у «Вхідні» й позначати їх «Важливими» — це зміна міток листа, нічого не видаляє й налаштувань не міняє. Його сервер просить **окремим токеном і лише для міток**: якщо делегування вже додано з двома scopes, холодні листи, читання відповідей і прогрів працюють як і раніше, лише зі спаму листи не виймаються (сторінка прогріву так і скаже). Додати третій — відредагувати той самий Client ID у тому ж списку.
3. Дати ключ у чаті розробки — він кладеться на сервер у змінну середовища, не в код:
   - `ESP_GMAIL_SERVICE_ACCOUNT_JSON` — вміст JSON-файлу, або
   - `ESP_GMAIL_SERVICE_ACCOUNT_BASE64` — той самий файл у base64 (якщо хостинг ламає багаторядкові значення).

Після цього «Пошта» → «Налаштування пошти» → «Пошта для розсилки» → «Перевірити доступ» на адресі скриньки: сервер просить у Google токен від імені цієї скриньки й читає її профіль. Нічого не надсилається.

## Що означають відповіді перевірки

| Відповідь | Що виправити |
|---|---|
| делегування не налаштоване / немає scopes (`unauthorized_client`) | крок 2: Client ID і scopes (`gmail.send`, `gmail.readonly` — обов'язкові; `gmail.modify` — для прогріву) |
| Google не прийняв скриньку (`invalid_grant`) | скриньки немає в домені, вона вимкнена, або годинник сервера збився |
| «Google називає її …» | введено псевдонім — відповіді прийдуть на основну адресу |

## Відправка заблокована

До приймання **ESP 11** справжні листи не йдуть: `GmailApiConnector.send` відмовляє (`SendingLocked`), поки сервер не запущено з `ESP_LIVE_SEND=1`, — і відмовляє ще до запиту токена. Без ключа працює заглушка (`StubGmailConnector`): відповідає як Gmail, нічого не шле в мережу. На ній будуються й тестуються лист, ліміти й ланцюжок (ESP 2–5).

## Змінні середовища ESP (усі — лише на сервері, не в коді)

| Змінна | Що вмикає | Коли задавати |
|---|---|---|
| `ESP_GMAIL_SERVICE_ACCOUNT_JSON` / `_BASE64` | справжній Gmail API замість заглушки | коли власник дасть ключ |
| `ESP_UNSUBSCRIBE_SECRET` (16+ символів) | постійний ключ посилань відписки (ESP 3); без нього посилання живуть до перезапуску | до ESP 11 |
| `ESP_SEQUENCE=on` | ланцюжок кампаній щохвилини надсилає те, що пора (ESP 5); без нього кампанії лише будуються й переглядаються | на тестовий цикл ESP 11 |
| `ESP_LIVE_SEND=1` | справжня відправка через Gmail; без неї `send` відмовляє | лише після приймання ESP 11 |
| `ESP_WARMUP_START` / `_STEP` / `_MAX` | план прогріву за замовчуванням (2 / 2 / 20); збережений на сторінці «Прогрів пошт» план головніший | якщо треба інший старт без сторінки |
| `ESP_WARMUP=off` | вимикає прогрів пошт на цьому сервері (за замовчуванням прогрів іде для скриньок, яким натиснули «Старт», — і лише з `ESP_LIVE_SEND=1`) | якщо треба зупинити все одразу |

«Стоп усе» на екрані «Листи» → «Кампанії» зупиняє відправку для всієї системи до наступного листа: його перевіряють і ланцюжок, і шлюз відправки.
